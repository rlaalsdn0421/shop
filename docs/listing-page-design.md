# 상품 목록 페이지 개편 설계

참고 화면(다른 쇼핑몰의 카테고리 페이지)처럼 **메인이 아닌 목록 페이지**를 바꾼다. 메인 페이지(`/`, 베스트·신상품·전체상품 섹션)는 그대로 둔다.

## 1. 범위

| 한다 | 하지 않는다 |
|---|---|
| 카테고리 목록 페이지(`/?category=바지` 등)의 모양 개편 | 메인 페이지와 그 안의 "전체상품" 섹션(`/#all`)·베스트·신상품 섹션 |
| 왼쪽 정렬 큰 제목, 오른쪽에 경로 "홈 > 바지(총 N개)", 굵은 검은 선 | 필터 줄(무료배송·혜택정보·배송유형·상품유형·가격대) |
| 정렬 줄 모양(선택한 항목에 ✓, 항목 사이 구분선, 왼쪽 정렬) | "40개씩 보기", 열 개수 바꾸기 버튼 |
| 큰 카드 4열 격자(데스크톱), 2열(모바일) | 카드 이미지 넘기기 점(●●●) |
| 목록 응답에 `total`(총 상품 수) 추가 | |

- 목록 페이지 = 주소에 `category`가 붙은 `/`. "전체상품"·"신상품"·"베스트" 메뉴(`/#all` 같은 같은 페이지 안 이동)는 이번에 바꾸지 않는다.
- 카드(`ProductCard`)의 내용은 그대로(이름·가격·할인·배송비 안내·해시태그). 하트도 그대로.

## 2. 서버

- 목록 응답 `ProductPage`에 `total`(그 카테고리의 전체 상품 수)을 더한다: `{ items, hasMore, total }`. `Page`가 이미 개수 조회를 하므로 추가 쿼리는 없다. 기존 필드는 그대로이고 새 필드가 늘 뿐이라 옛 화면과도 호환된다.
- 베스트 목록 등 다른 응답은 바꾸지 않는다.

## 3. 화면

- 목록 페이지(카테고리가 있을 때만) 머리: `<h1>`은 카테고리 이름(왼쪽, 크고 굵게), 같은 줄 오른쪽에 `<nav aria-label="현재 위치">` "홈 › {카테고리}(총 {total}개)". 홈은 `/` 링크. `total`이 없으면(옛 서버) "(총 N개)" 부분만 생략한다. 그 아래 굵은 검은 선(`border-b-2`).
- `SortTabs`: 목록 페이지에서는 새 모양(`variant="listing"`)을 쓴다. 왼쪽 정렬, 선택한 항목은 굵게 + ✓(스크린리더에는 현재 선택임을 알린다), 항목 사이에 가는 세로 구분선. 홈의 전체상품 섹션은 지금 모양 그대로.
- `InfiniteProductGrid`: 목록 페이지에서는 `variant="listing"`으로 큰 4열(`lg:grid-cols-4`, 태블릿 3열, 모바일 2열)과 넉넉한 간격. 홈에서는 지금 모양 그대로.
- 상품이 하나도 없는 카테고리는 "이 카테고리에는 아직 상품이 없어요"를 보여 준다(지금 문구가 있으면 그대로).
- 무한 스크롤, 정렬 동작, 하트, 접근성은 그대로 유지한다.

## 4. 알고 두는 한계

- 참고 화면의 필터 줄·열 개수 버튼·이미지 점은 만들지 않는다(실제로 동작할 필터 기준이 아직 없다).
- ("전체상품"·"신상품"·"베스트"의 별도 페이지는 5절에서 다음 PR로 만든다.)

## 5. 전체상품·신상품·베스트 별도 페이지

메뉴의 "베스트"·"전체상품"·"신상품"이 메인 페이지 안 이동(`/#best` 등)이 아니라 **각자의 페이지**로 가고, 카테고리 페이지와 같은 새 모양을 쓴다. 메인 페이지(`/`)와 카테고리 페이지(`/?category=`)는 그대로다.

| 메뉴 | 주소 | 내용 |
|---|---|---|
| 전체상품 | `/products` | 전체 상품, 정렬 줄(`?sort=`, 기본 인기도순), 무한 스크롤, "홈 › 전체상품(총 N개)" |
| 신상품 | `/new` | 최신 등록순 고정(정렬 줄 없음), 무한 스크롤, "홈 › 신상품(총 N개)" |
| 베스트 | `/best` | 기간 탭(`?best=realtime\|weekly\|monthly`, 기본 실시간), 순위 표시가 있는 카드 최대 20개(한 번에), "홈 › 베스트(총 N개)"(N = 보이는 개수) |

- 서버는 바꾸지 않는다(전체·신상품 목록은 이미 `total`이 있고, 베스트는 서버가 최대 20개를 준다).
- `ListingHeader`(제목 `<h1>` + "홈 › …(총 N개)" 경로 + 굵은 선)를 공용 컴포넌트로 뽑아 카테고리 페이지와 새 세 페이지가 함께 쓴다. 카테고리 페이지의 화면(DOM)은 그대로여야 한다.
- 정렬 줄과 베스트 기간 탭은 `variant="listing"` 모양을 쓰고, 링크 주소가 자기 페이지(`/products?sort=…`, `/best?best=…`)를 가리키도록 기준 경로를 받는다. 메인 페이지의 탭과 링크는 지금 그대로(`/?sort=…#all`, `/?best=…#best`).
- 메뉴: "베스트"→`/best`, "전체상품"→`/products`, "신상품"→`/new`. 현재 메뉴 표시는 주소(`pathname`)로 정한다(`/best`, `/products`, `/new`). 카테고리는 기존처럼 `/?category=`.
- 메인 페이지의 베스트·신상품 섹션 "전체보기" 링크는 `/best`(보고 있던 기간 유지)와 `/new`로 바꾼다. 메인의 전체상품 섹션은 그대로.
- 빈 목록 문구: 전체상품 "아직 상품이 없어요", 신상품 "아직 신상품이 없어요", 베스트 "아직 베스트 상품이 없어요". 전체·신상품 목록을 못 불러오면 카테고리 페이지처럼 오류 화면, 베스트는 메인처럼 그 자리에 "상품을 불러오지 못했어요".
- 옛 주소(`/#all`, `/?sort=popular#all`)는 메인 페이지로 계속 열린다(막지 않는다).
